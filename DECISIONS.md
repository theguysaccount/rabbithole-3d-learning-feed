# DECISIONS

1. **YouTube clips only, through the official embedded player.** The brief requires it, and it removes hosting cost entirely. Videos play from youtube-nocookie.com via the IFrame Player API; nothing is downloaded, re-hosted, covered or restyled. Start and end times use the player's own parameters. Non-embeddable videos are refused in the builder and skipped in the player.
2. **Axes: vertical = sequence, horizontal = depth.** Swipe up (↓ key) for the next clip on the current track, left (→) to go deeper, right (←) to back out to the clip the track hangs from. This matches Jack's "left, right, down swipe for next video" note and keeps "next" the most common, easiest gesture. Autoplay at the end of a deeper track returns to the main track rather than running depth-first through everything.
3. **Swipes on a pad below the video, never on it.** The player is a cross-origin iframe that swallows touches, and covering it would break YouTube's controls and its embedding rules. The pad has `touch-action: none` so swipes don't scroll the page; buttons and arrow keys do the same things. On phones the video runs edge to edge so the player always gets at least 200 x 200 pixels.
4. **The share link is the storage.** The cleaned path is deflate-compressed into the `#h=` fragment (`1z.` prefix; `1j.` plain JSON where CompressionStream is missing). No server, no accounts, nothing to moderate or lose; browsers don't send fragments to servers. Trade-off: editing means sharing a new link; long paths make long links (the builder warns above 6,000 characters). Hosted short links are part of the paid tier.
5. **Titles and embeddability from oEmbed, not the Data API.** youtube.com/oembed is public, needs no key and allows browser requests; 200 means embeddable, 401 means embedding is off, 404 means gone. The same endpoint drives the scheduled embed check.
6. **Builder: outline plus drag and drop.** An outline (indent/outdent like Tab/Shift+Tab) works by keyboard and on touch; pointer-event drag and drop (before, after, or into a clip's deeper track) covers the brief's "drag-and-drop editor" with mouse, pen and touch alike.
7. **Demo paths from embeddable educational channels, credited and linked.** 3Blue1Brown, Crash Course Computer Science and Ben Eater, each video verified with oEmbed on 2026-11-22. Titles and notes are short descriptions in our own words; each demo page lists every video with its channel and a link to YouTube. No start/end times on demo clips: we didn't pick minute marks we hadn't checked.
8. **Tests never depend on YouTube.** The deploy's end-to-end test swaps in a stand-in for the IFrame API with the same calls and events; the live self-test additionally loads the real API. A YouTube outage can't block a deploy; a YouTube API change still gets noticed.
9. **Thumbnails from i.ytimg.com only where they navigate to the embedded player** (map, builder rows, demo cards linking to demo pages).
10. **Domain: build on top, don't replace.** entermyrabbithole.com already serves a live, separate "Rabbit Hole" site on Vercel. This tool should become a subdomain (for example videos.entermyrabbithole.com) linked from it, decided by the domain rollout session. Nothing here changes DNS. Outcome: live at videos.entermyrabbithole.com since 2026-11-22.
11. **Name and tone.** "Rabbit Hole", the name in Jack's notes. The "3D feed" phrase is used once, as an explanation, not as the brand.
